# 候选资格与确认访问协议

本协议限定于资格登记，状态 `CLOSED`，没有科学数据或性能访问许可。当前 9 个候选全部登记，不依据性能删选；`2-20`、`8-13` 仅满足原10TX与 D3–D4 每组100个 raw 包的计数兼容性，尚未证明历史独立性。

## 资格条件

1. 身份：官方 Full RX 节点与原 ManyRx32 差集一致，原10TX的物理标识到模型类序保持固定。不得用相似类号代替设备标识；硬件序列号未知时如实披露。
2. 数据支持：保持原10TX与原 CRD D3–D4评估范围，每TX/RX/日预算100个 raw 包。不因缺类、缺日、短缺而事后删掉原TX、切换到EQ或降低预算以扩大“合格”集合。未来若要采用不同任务，必须另行命名和预注册，不能称为原CRD的同协议独立确认。
3. 历史独立性：需有覆盖既有研究的可核验数据使用/查看记录，排除候选参与训练、验证、BN校准、超参数或方法选择、错误分析、人工性能查看。只有本机无命中或不在ManyRx清单不足以合格。官方SingleDay曾包含候选的事实需在记录中明确核对。不能把 UNKNOWN 自动变成否。
4. 队列冻结：将全部满足上述条件的 RX 及 TX/日期/包键选择规则、来源版本、文件哈希写入不可变 cohort manifest，独立提交后才考虑 IQ 获取。若没有任何合格RX，记录“无新增独立确认”，继续把既有CRD结果明确标为回顾性benchmark。

## 任何未来评分前必须另行冻结的内容

- 完成 C 与 M0 的既定出口；方法、架构、预处理、模型选择、训练预算、随机流以及候选权重先冻结；确认数据不得用于任何训练、调参或 BN 处理。
- 独立确认的最终训练/选模/评分协议须另行预注册并通过工程验收。本元信息任务及 C 的注册均不许可 full-fit18 重拟合、打开新候选 IQ 或读取历史 held6/target8。
- 固定原模型类序、包数、样本键和覆盖失败处理；一次性运行所有预定方法/训练流，完整归档失败和结果，不按确认性能更换方法、种子或队列。
- 预先规定 RX 等权 Accuracy、Macro-F1、最差RX、TX×RX风险、跨流一致性及成本报告。若只有两台新RX，明确是固定小队列条件结果，不把包级样本量当作独立RX样本量，也不声称总体接收机泛化已被证明。

当前不满足历史独立性和冻结队列条件，所以评分入口不开放。本任务无需通过追加种子、额外归因训练或试评分来填补这些条件。
