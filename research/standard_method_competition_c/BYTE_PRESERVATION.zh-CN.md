# 发布字节与训练字节的核对

这是跨平台发布补充，不是新的研究或训练阶段。Git 的 CRLF→LF 文本规范化会使原始文件的 SHA-256 与 GitHub 下载字节的 SHA-256 不同。原预注册及训练记录的哈希按实际执行机器上的原字节计算；这些记录和冻结代码均保留，没有改写来适配 Git。

以提交 `efcb1c0` 为基准，对原发布清单和冻结代码/证据的并集共 156 个文件核对：44 个文件存在换行表示差异，其中 11 个属于本轮三个工作包的原发布清单。全部差异都满足“原字节仅将 CRLF 替换为 LF 后，与 GitHub blob 字节完全相同”；未发现其他内容差异。83 个原训练冻结文件，加上独立 QA 的 2 个代码/测试文件，共 85 个登记哈希均仍与本地原字节相符。

- [字节对照](BYTE_REPRESENTATIONS.json)保留基准提交、原字节哈希、GitHub blob 内容 SHA-256 和逐文件比较结果。这里的 GitHub 内容哈希不是 Git 对象 ID。对照是该基准时点的快照；后续仅发布说明/清单的版本变化由最终清单记录。
- [原字节档](FROZEN_EXECUTION_BYTES.zip)无损保存 99 个文件：全部 85 个登记文件、执行登记/预检材料，以及存在换行差异的补充元数据。已逐文件解压往返核验；不含 IQ、权重或逐包数组。
- 需要重建登记时的精确字节时，在隔离副本中按压缩档的仓库相对路径恢复，再核对旧登记哈希。不能把规范化换行后的 Git 文本直接当作原始哈希输入，也不必修改实验配方或重新训练。
- [最终发布清单](EXECUTION_MANIFEST.json)第二版同时记录原字节 SHA-256 与当前发布 blob 内容 SHA-256；原 `MANIFEST.json` 等历史登记不变。

完整 ANALYSIS.json.gz、其解压结果、checkpoint 哈希和科学决策均未改变；没有重新评分或增加拟合。这次补充解决的是材料从 GitHub 取回后如何按原字节复核的问题。
